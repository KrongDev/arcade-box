# 아케이드박스 서버 v2 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버를 계정·통일 코인·상품·보유·주문·게임 목록의 정본으로 다시 만들어, 게임을 서버 배포 없이 추가하고 코인으로 사서 받을 수 있게 한다.

**Architecture:** Node 기본 `http` 위에 도메인별 디렉토리(`account`, `wallet`, `product`, `entitlement`, `order`, `game`, `play`, `reward`, `asset`, `admin`, `view`, `shared`)를 둔다. 저장은 Drizzle로 PostgreSQL 스키마 `app`에 하고, 규칙은 DB를 모르는 순수 함수로 둔다. 운영은 서버 컨테이너 안의 명령줄 도구로 한다.

**Tech Stack:** TypeScript (Node 24가 바로 실행), Drizzle ORM 0.45 + drizzle-kit 0.31, PostgreSQL 17 (`pg`), `jose` (ID 토큰 확인), 테스트는 `node --test` + PGlite.

**Spec:** `docs/superpowers/specs/2026-11-26-server-v2-design.md` — 테이블(5.2), 일부러 중복한 곳(5.3), 계정(5.4), API(5.10), 명령(5.11), 코드 구조와 경계(5.14), 공통으로 뽑는 기준(5.15)은 그 문서가 정본이다.

## Global Constraints

- 지울 수 있는 문법만 쓴다: `enum`, 데코레이터, 생성자 매개변수 속성 금지 (`erasableSyntaxOnly`). 상대 import에는 `.ts` 확장자를 쓴다.
- 테이블은 PostgreSQL 스키마 `app`에 만든다. v1 테이블(`public`)은 읽지도 쓰지도 지우지도 않는다.
- 런타임 의존성은 `drizzle-orm`(0.45의 최신 패치), `pg`, `jose`뿐이다. 개발용은 `drizzle-kit`(0.31의 최신 패치), `@electric-sql/pglite`. 버전은 정확한 값으로 고정한다.
- 도메인 경계(스펙 5.14): 다른 도메인의 것은 그 도메인의 `index.ts`로만 가져온다. 예외는 외래 키를 거는 `schema.ts`뿐이다. `shared`는 도메인을 가져오지 않는다. 의존은 `admin`·`asset`·`account` → `game`·`wallet` → `product` → `entitlement` → `play`·`reward`·`order` → `view` 방향으로만 간다.
- 공통으로 뽑는 것은 스펙 5.15의 표대로만 한다. 표에 없는 닮은 코드는 세 번째로 나올 때까지 따로 둔다.
- 코인은 `wallet`의 `applyCoins`만 바꾼다. 다른 코드는 `wallets`·`coin_ledger`에 쓰지 않는다.
- 운영 명령 가운데 무언가를 바꾸는 것은 `--reason` 필수, 요약 확인, `admin_actions` 기록을 `admin`의 `mutation` 틀로만 한다.
- 새 포트와 관리용 HTTP 경로를 만들지 않는다. 키·토큰·영수증·기기 비밀값을 로그에 남기지 않는다. 테스트에 쓰는 키는 테스트 안에서 만든다.
- ID 토큰에서 `sub`만 쓴다. 이메일과 이름을 저장하지 않는다.
- 오류 응답은 `{ "error": { "code", "message" } }`이고 메시지는 해요체다. 주석과 테스트 이름은 한국어로 쓴다.
- 테스트는 바깥 서비스 없이 돈다: DB는 PGlite, 토큰 확인기와 시계는 주입한다.
- 커밋은 `server-v2` 브랜치에만 한다. 푸시, 운영 서버 배포, 운영 DB 변경은 사용자 확인 뒤에 한다.
- 매 작업의 끝 확인: `cd server && npm test` 통과, `npm run typecheck` 통과.

## Review Focus

1. 두 요청이 같은 순간에 같은 지갑을 쓸 때 (연타한 구매, 판 결과와 출석이 겹침) — 잔액이 0 아래로 내려가거나 기록과 어긋나지 않고, 같은 상품이 두 번 팔리지 않아야 한다. (Task 5, 11, 12, 14: 진짜 PostgreSQL 동시성 테스트)
2. 통신이 끊겨 앱이 같은 요청을 다시 보낼 때 — 코인·구매·판 결과가 한 번만 반영되고 처음과 같은 답을 받아야 한다. 같은 키로 다른 내용을 보내면 거절해야 한다. (Task 5, 10, 12)
3. 일이 중간에 실패할 때 (판은 저장됐는데 코인 반영에서 오류) — 아무것도 남지 않아야 한다. (Task 10: 지갑 상한 제약으로 실패를 일으키는 테스트)
4. 말이 안 되는 입력 — 64KB 넘는 본문, 깨진 JSON, 숫자가 아닌 값·음수·소수·NaN 코인, `..`이 든 아이콘 이름, 숫자가 아닌 버전 — 서버가 죽지 않고 4xx로 답해야 한다. (Task 1, 7, 10)
5. 한국 날짜가 바뀌는 순간과 세션이 끝나는 순간 — 23:59:59와 00:00:00의 출석이 서로 다른 날로 세어지고, 만료 1초 전 세션은 되고 만료된 세션은 안 돼야 한다. (Task 3, 11)

## v1이 하던 일 — v2에서의 자리

v1 서버(`server/src/app.ts`, `domain.ts`)가 지금 하는 일을 한 줄에 하나씩 적었다. `K`는 v2가 이어 가는 것, `D`는 일부러 없애는 것이다. 미션 노드의 통과 기준은 이 번호를 가리킨다.

### Task 1: 바탕 — shared, 테스트 틀, 경계 테스트

**Files:**
- Modify: `server/package.json` (의존성, `"test": "node --test 'test/**/*.test.ts'"`, `"test:pg": "node --test 'test-pg/**/*.test.ts'"`, `"db:generate": "drizzle-kit generate"`, `"cli": "node src/cli.ts"`), `server/tsconfig.json` (`include`에 `test-pg`, `drizzle.config.ts`)
- Create: `server/drizzle.config.ts` (`schema: './src/schema.ts'`, `out: './drizzle'`, `dialect: 'postgresql'`, `schemaFilter: ['app']`), `server/src/schema.ts`, `server/src/shared/{config,errors,time,crypto,validate}.ts`, `server/src/shared/db/index.ts`, `server/src/shared/http/{index,rate-limit}.ts`
- Test: `server/test/helpers/{db,http,clock}.ts`, `server/test/shared/{http,time,crypto,db,validate}.test.ts`, `server/test/boundaries.test.ts`

**Interfaces:**
- Produces:
  - `errors.ts`: `class RuleError extends Error { status: number; code: string; detail?: Record<string, unknown> }` (생성자 `(status, code, message, detail?)`)
  - `time.ts`: `type Clock = () => Date`, `kstDate(now: Date): string` (YYYY-MM-DD)

- 클라이언트(`src/game/api.ts` 등)는 아직 `/v1`을 부른다. 2번 작업에서 바꾼다. 그때까지 운영 서버에 v2를 배포하지 않는다 (배포는 사용자 확인 뒤).

- 구글·애플 결제 확인, 애플 로그인, 계정 삭제 안내 웹 페이지는 3번 작업이다.
